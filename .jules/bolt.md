## 2026-08-20 - GameBoard O(1) Map Lookups & Standings Memoization
**Learning:** In components rendering repetitive grid structures (like 40 Monopoly board cells), calling `.find()` or `.filter()` inside the cell loop results in O(P * C) complexity per render frame. Furthermore, unconditional calculations of aggregated values (like net worth standings) inside component renders execute on unrelated re-renders. Precalculating Map lookups (`playerPositionsMap`, `propertyOwnersMap`) and standings inside `useMemo` before rendering cells reduces per-cell lookups to O(1) and skips recalculations when game state references are unchanged.
**Action:** When rendering grid/list components with entity relationships, build lookup Maps in `useMemo` at the container level instead of running array queries inside child map functions.
