## 2026-08-20 - Custom Accordion Accessibility
**Learning:** When implementing custom accordion headers (like the player rows in `PlayerPanel.tsx`), developers often use `onClick` on non-interactive `<div>` elements. This completely hides the toggle functionality from keyboard users and screen readers, and requires manual `tabindex` and `keydown` event handling to fix if left as a `<div>`.
**Action:** Always replace non-interactive toggle wrappers with semantic `<button type="button">` elements. This provides native keyboard support (Space/Enter). Use CSS utility classes (like `w-full text-left focus-visible:outline-none focus-visible:ring-2`) to normalize the button's appearance while providing visible focus indicators, and always apply `aria-expanded` and `aria-controls` to link the button to its expandable content.
