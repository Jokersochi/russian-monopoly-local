# 🎲 Русская Монополия

Интерактивная экономическая настольная игра с российскими городами и объектами. Текущая версия — локальная hot-seat партия на 2–6 игроков с расширенной экономикой, сохранением прогресса и адаптивной premium-доской.

## Текущее состояние

Реализовано:

- локальная партия на 2–6 игроков;
- российская тематическая доска из 40 клеток;
- покупка недвижимости и оплата аренды;
- дубли, тюрьма и переход через Старт;
- аукционы;
- дома и отели;
- залог недвижимости;
- сделки между игроками;
- карточки событий и микро-события;
- банкротство и завершение партии;
- автосохранение и save slots в браузере;
- четыре локали: RU / EN / DE / ES;
- адаптивный интерфейс и premium tabletop UI;
- TypeScript, ESLint, production build и CodeQL в CI;
- Docker и Vercel deployment configuration.

**Online Core Beta:** серверные комнаты на 2–6 человек, защищённая сессия игрока, восстановление после перезагрузки браузера, авторитетные серверные броски/покупки/аренда/налоги/тюрьма, чат. Доступно по `/online` при запущенном API. Это отдельный упрощённый режим; полный перенос локальной экономики, аукционы, дома, сделки, рейтинг и matchmaking пока не реализованы.

## Локальный запуск

Требования: Node.js 20+ и npm.

```bash
git clone https://github.com/Jokersochi/russian-monopoly-local.git
cd russian-monopoly-local
npm ci
npm run dev
```

Vite dev server настроен на:

```text
http://localhost:8080
```

Если проект запускается через внешний dev-контейнер или прокси, порт может быть проброшен на другой адрес, например `127.0.0.1:3000`.

## Архитектура

```text
src/
  components/      игровое поле, панели действий, UI
  contexts/        GameContext и LocaleContext
  data/            клетки, карточки, события, локали
  pages/           основные страницы
  types/           доменные TypeScript-типы
  hooks/           переиспользуемые React hooks
  lib/             вспомогательные функции
```

Локальная hot-seat партия работает на клиенте и сохраняется в `localStorage`. Онлайн-партия работает на сервере и сохраняется в приватный файловый снимок. Это два отдельных режима с разным набором правил.

## Online Core Beta — запуск

Для разработки откройте два терминала:

```bash
npm ci
npm run dev:server
```

```bash
npm run dev
```

Откройте `http://localhost:8080/online`. Создайте комнату, отправьте ссылку другому игроку и начните партию. Vite перенаправляет `/api` на локальный сервер (порт 3001).

Для Docker: `docker compose up --build`, затем `http://localhost:3002/online`. Данные сохраняются в именованном Docker volume и переживают пересоздание контейнера (не используйте `docker compose down -v`, если хотите сохранить партии). Nginx перенаправляет `/api` на контейнер `online`.

Проверки: `npm run typecheck:server`, `npm test`, `npm run build:server`. Ключ сессии сохраняется **только в localStorage**, не в URL. Сервер не принимает клиентские результаты бросков и проверяет принадлежность хода.

**Online Core v2:** партии, комнаты, хеши токенов игроков и чат сохраняются в приватный JSON-снимок атомарной записью и восстанавливаются после перезапуска одного сервера. Docker Compose использует постоянный volume `online-data`; для локального Node данные хранятся в `.online-data/rooms.json` (или путь `ONLINE_DATA_FILE`). События передаются по аутентифицированному SSE-потоку, без постоянного опроса. Браузер автоматически переподключается.

**Ограничения Beta:** файловое хранилище рассчитано на **один процесс** и не заменяет PostgreSQL/Redis для горизонтального масштабирования. Нет PostgreSQL/Redis, аукционов, строительства, сделок, рейтинга и матчмейкинга. В Docker Compose базовые ограничения API уже настроены в nginx: в среднем 5 запросов/с с пиком до 20 и до 25 одновременно обрабатываемых подключений на IP (включая долгоживущие SSE). За внешним reverse proxy требуется отдельно настроить доверенный реальный IP клиента, иначе несколько пользователей могут разделить один лимит. Эти меры не заменяют защиту на уровне инфраструктуры. Не запускайте публичный сервис без HTTPS, резервного копирования данных и дополнительной проверки безопасности. Развёртывание только Vite-статики на Vercel не запускает Online API: необходим отдельный Node-сервис и маршрутизация `/api`.

## Следующий этап: Production Online

Приоритеты после Online Core v2:

1. перенести в серверный движок оставшиеся правила локальной партии: аукционы, дома, отели, залог и сделки;
2. заменить файловый snapshot на транзакционную PostgreSQL-базу и добавить Redis для масштабирования;
3. добавить миграции схемы, резервное копирование, восстановление и аудит событий партии;
4. добавить rate limiting на reverse proxy, HTTPS, мониторинг, лимиты ресурсов и защиту от злоупотреблений;
5. реализовать matchmaking, рейтинг и статистику;
6. добавить AI-игроков, работающих через тот же серверный engine;
7. расширить интеграционные и E2E-тесты до нескольких браузеров, сетевых обрывов и восстановления после рестарта.
